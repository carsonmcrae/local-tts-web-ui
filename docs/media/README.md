# Videos: what they show and how they were made

Two videos are used in the README, the wiki and each GitHub Release. Both are generated by scripts in
[`scripts/media`](../../scripts/media), so anyone can reproduce them.

> **Before the rename.** The current videos and the screenshots in [`docs/images`](../images) were
> recorded when the app was called Local TTS, so its header and logo appear under that name. The
> files were renamed, not re-recorded. Regenerate them with `npm run media:screenshots`, then
> `npm run media:promo` and `npm run media:demo`, and remove this note.

## `ttsnative-demo.mp4`: the app, recorded as it runs

A real screen recording of the production build with the real models: Kokoro on the CPU and Chatterbox
Turbo on an NVIDIA RTX 3080, under Windows 11. [`record-demo.mjs`](../../scripts/media/record-demo.mjs)
starts an isolated server with an empty library and drives the UI like a person would:

1. upload a PDF
2. choose a voice and press Play
3. jump between chapters, and keep listening as narration carries into the next one
4. compare voices
5. create a voice in Voice Studio
6. export a chapter
7. switch to the dark theme

Frames come from Chromium's screencast at 1920×1080.

- **The sound is the app's own audio.** Headless Chromium records no sound, so the recorder logs every
  clip the app plays (when it starts, pauses and ends) and downloads that clip as it starts playing.
  [`demo-assemble.mjs`](../../scripts/media/demo-assemble.mjs) then places each clip at the moment it
  played. Nothing is re-synthesised or edited, apart from one loudness normalisation for the whole track
  (−16 LUFS).
- **Overlays.** A cursor, numbered step captions and the end card are drawn over the page by
  [`demo-page.js`](../../scripts/media/demo-page.js). They don't change what the app does.
- **The document** is "The Lighthouse Keeper", a three-chapter story written for this project
  ([`make_demo_pdf.py`](../../scripts/media/make_demo_pdf.py)), so the video contains no third-party
  text.
- **The cloned voice is synthetic.** Its reference recording is the built-in Kokoro voice "George"
  (`bm_george`) reading the Voice Studio passage, not a real person. The video says so on screen.
- **Captions** (`ttsnative-demo-captions.vtt`) give the sentences actually narrated and the on-screen
  steps, with their real timings.

## `ttsnative-promo.mp4`: the 45-second overview

A motion graphic built from the app's own screenshots ([`docs/images`](../images)), fonts and colours
([`promo/promo.html`](../../scripts/media/promo/promo.html) and [`promo.js`](../../scripts/media/promo/promo.js)).
[`render-promo.mjs`](../../scripts/media/render-promo.mjs) renders it frame by frame in headless Chromium.

- **Voice-over:** spoken by TTSNative itself. Each line is generated through the app's API with the
  Kokoro voice "Heart" (`af_heart`), and the render fails if a line overruns its scene.
- **Music and effects:** synthesised in code by [`promo-music.mjs`](../../scripts/media/promo-music.mjs).
  The pad, bass, arpeggio, whooshes and chime come from oscillators and seeded noise. There are no
  samples, loops or third-party recordings, so there is nothing to license. The music ducks under the
  voice, and the mix is normalised to −16 LUFS.
- **Captions** (`ttsnative-promo-captions.vtt`) are the voice-over script with its timings.

## Regenerating

You need the installed Kokoro model, FFmpeg 7 or newer (on `PATH`, or set `LTTS_FFMPEG` to its full
path), and for the Voice Studio part of the demo, the optional Chatterbox engine. Without Chatterbox, the
demo skips that step.

```bash
npm run media:demo
npm run media:promo
```

Working files (frames, the uncompressed masters and the individual clips) go to `.tools/media/`, which
Git ignores. Review the result before committing: the demo is a live recording, so timings vary from run
to run.
