# Threat model

> **In short:** the app is single-user and local, but it parses untrusted files, downloads third-party
> artifacts and runs a web server. The main threats are malicious documents, a malicious website in
> the same browser talking to `127.0.0.1`, tampered downloads, and accidental network exposure.

## Assets

Documents and their text, bookmarks and notes, voice recordings (biometric data), generated audio, the
local filesystem, and the integrity of installed model files and Python/npm dependencies.

## Trust boundaries

1. **Browser ↔ local server.** Any website the user visits can make requests to `127.0.0.1`.
2. **Uploaded files → parsers.** Documents and audio come from anywhere.
3. **Internet → model store / package managers.** Downloads during setup and engine installation.
4. **Server ↔ cloning worker.** A separate process with large third-party dependencies.
5. **LAN (opt-in only).** Other devices when LAN mode (pairing) or the older network mode is enabled.
6. **Local programs ↔ speech API (opt-in only).** Scripts and tools on this computer calling `/v1`.

## Residual risks

- **Only Linux has a per-process memory limit** in the sandbox (`RLIMIT_AS`). Windows has no
  equivalent, and macOS reserves more virtual address space at start-up than any useful cap allows.
  The timeout, archive and text limits still apply everywhere.
- **The optional Chatterbox environment carries one reviewed, unreachable advisory**: `torch`
  2.11's `torch.jit.script` issue (the fix needs a torchaudio that does not exist yet, and nothing
  calls `torch.jit`). `npm run security` audits both extras and fails on anything else
  ([supply-chain.md](supply-chain.md#known-advisories-in-the-optional-chatterbox-environment)). The
  default Kokoro reader does not install them.
- **PDFium and libxml2 are native code.** They are mature and fuzzed, and run in a separate, killable
  process, but a memory-safety bug could still compromise that process.
- **LAN and network modes use plain HTTP.** Pairing (or the token) protects access, but not
  confidentiality on the network.
  - Someone who can watch the Wi-Fi traffic can read the documents and audio a device opens, and its
    cookie. That is anyone on an open network, or anyone on a WPA2 network who knows its password.
  - LAN mode limits a copied cookie to the device's own address and to 30 days.
  - An attacker who can also take over that address, or change traffic (ARP spoofing, a rogue access
    point), can use the session or inject script into the device's page until the device is removed.
    So can someone who catches the pairing request itself and blocks it, then uses its code first.
  - Network mode's token has neither limit.
  - Browsers also block the microphone and service workers on non-HTTPS origins. HTTPS would need a
    certificate the phone trusts, which TTSNative doesn't create or install; the options are in
    [lan-https.md](../research/lan-https.md). See [LAN access](../guides/lan-access.md).
- **Cookies don't keep to a port, and LAN addresses get reused.** A device's cookie is also sent to
  any other service on the same address, whatever its port. It is also sent to whichever device
  gets that address after DHCP hands it to someone else, if the phone opens it. The address binding and
  the 30-day limit keep such a copy short-lived. Network mode's token cookie has neither.
- **Requests through a proxy on this computer look local.** A reverse proxy or tunnel on this
  computer (for example Tailscale Serve) forwards to `127.0.0.1`. Its requests are refused today,
  because their Host isn't a loopback name. But adding that name to `extra_allowed_hosts` would treat
  every device behind it as the person at the computer, skipping pairing. Don't. A fix needs the
  owner's decision ([lan-https.md](../research/lan-https.md#3-tailscale-serve-and-headscale)).
- **Adapter detection is by name.** A VPN or virtual adapter with an unusual name is offered as an
  ordinary network. The address list shows each adapter's name, so check it.
- **GPL components** (espeak-ng, phonemizer) are runtime dependencies; see the license inventory.
- **The Chatterbox environment** contains a large third-party dependency tree (PyTorch, transformers).
  It is isolated, locked and only installed on request, but it is not audited line by line.
